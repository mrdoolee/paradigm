# 고전 도트 RPG의 UI·UX 패턴과 NOS 플랫폼 적용안

작성일: 2026-10-14
짝 문서: `2026-10-14-classic-rpg-architecture-study.md` (구조 조사). 이 문서는 같은 원본(GBC 시절 탑다운 RPG)에서 **화면 구성과 조작 규칙**만 따로 정리한다.

## 0. 먼저 읽을 것

**에셋은 넘기지 않는다.** `CLAUDE.md`는 참고 게임의 이름·캐릭터·이미지·음악 사용을 금지한다. 원본의 도트 그림, 글꼴, 창 테두리, 소리는 추출하지 않았고 이 프로젝트로 옮기지도 않는다. 이 문서는 **"무엇을 어떻게 배치하고 어떻게 조작하게 하는가"라는 규칙과 수치**만 다룬다. 규칙은 이 프로젝트의 도트 체계(`src/art`, 게임별 `STYLE.md`)로 새로 그린 그림에 적용한다.

**근거 등급.** 이 문서를 처음 쓸 때는 모든 항목이 B등급(공개 사양과 널리 알려진 화면 규칙)이었다. 그 뒤 에뮬레이터로 실제 화면을 캡처해 대조했고(짝 문서 `2026-10-14-classic-rpg-asset-forms.md` 1절), 다음은 **A등급으로 올랐다**: 화면 160×144, 타일 8×8, 대화 상자 위치·크기(하단 전폭 20×6 타일), 시작 메뉴 크기(8×12 타일), 옵션 화면(전체 20×18 타일), ▶ 커서와 ▼ 넘김 표시, 메뉴 설명 줄. 나머지(입력 반응 속도, 걸음 간격 등)는 여전히 B등급이다.

## 1. 화면 기준값 (B)

| 항목 | 값 | 비고 |
|---|---|---|
| 화면 | 160 × 144 px | 가로세로비 10:9 |
| 타일 | 8 × 8 px, 화면은 20 × 18 타일 | |
| 캐릭터·이동 단위 | 16 × 16 px (타일 2×2), 한 걸음 = 한 칸 | 이 프로젝트의 `tileSize: 16`과 같다 |
| 색 | 팔레트 하나 = 4색. 배경 8개 + 물체 8개 | 한 그림이 쓰는 색이 작다 |
| 글꼴 | 8 × 8 px 글자 | 이 프로젝트는 본문 16px 이상 규칙이 있어 해당 없음 |

**읽는 법.** 작은 화면과 적은 색은 원본이 "그림 스타일의 일관성"을 얻은 이유이기도 하다. 모든 그림이 같은 제약 안에서 만들어졌다. 이 프로젝트의 `nos-art` 스킬이 이미 "팔레트 16색 이내, STYLE.md 한 장"을 요구하므로 방향은 같다.

## 2. 화면 구성 원칙

| # | 원칙 | 원본의 모습 | 이 프로젝트의 현재 상태 |
|---|---|---|---|
| L1 | **세계 창이 화면의 주인공이다.** UI는 필요할 때만 올라온다 | 필드에서는 세계가 거의 전체. 대화·메뉴는 일부를 덮는다 | `layoutFor`가 세로·가로·넓은 화면 3종을 고르고 세계 창 최소 높이를 지킨다. 같은 방향 |
| L2 | **대화 상자는 화면 아래에 고정**하고 위치가 바뀌지 않는다 | 하단 약 1/3, 한 번에 2줄 | `DialogueBox`가 하단 판. 한 화면 3문장·160자 기준(스펙 ③-a) |
| L3 | **넘김 표시**(▼)가 깜빡이며 입력을 기다린다 | 마지막 줄 끝에 ▼ | 이미 있다(`.dialogue-more`, 800ms 깜빡임) |
| L4 | **선택지는 대화 상자 위에 작은 창**으로 겹쳐 뜬다. 커서(▶)가 항목을 가리킨다 | 오른쪽 위 작은 창, 예/아니오 | `DialogueStep.choices`가 있다. 위치·커서 규칙은 코드로 확인 필요 |
| L5 | **메뉴는 스택**이다. 열면 쌓이고 B로 한 장씩 닫힌다. **커서 위치를 기억**한다 | 도감·가방 등을 열었다 닫아도 커서가 그대로 | `modalStack`이 스택을 만든다. 커서 기억은 없다 |
| L6 | **상태 표시는 한 곳에 요약**한다 | 저장 전 요약창(위치·시간·진행도) | `StatusBar`가 장·장소·날짜·목표를 보인다. 저장 요약은 스펙 ④-a의 이어하기 안내에서 다룬다 |

## 3. 조작 원칙

| # | 원칙 | 원본의 모습 | 이 프로젝트의 현재 상태 |
|---|---|---|---|
| I1 | **버튼 의미 고정:** A = 확인·상호작용·다음, B = 취소·뒤로·빨리보기. 모든 화면에서 같다 | A·B·시작·선택 4버튼 | 같다(`useInputTarget`, `DialogueBox` 주석: A 넘기기, B 한꺼번에 보기) |
| I2 | **입력 맥락은 하나.** 대화가 열려 있으면 방향키가 아래(필드)로 새지 않는다 | 상태 하나가 입력을 독점 | 같다(`useInputTarget` 스택, 필드는 `talk === null`일 때만 활성) |
| I3 | **방향 전환과 이동을 구분**한다. 짧게 누르면 방향만 바뀌고, 계속 누르면 걷는다 | 정지 상태에서 방향이 다른 키는 먼저 몸을 돌린다 | 막혔을 때만 방향이 바뀐다(`tryStep`). 짧게 눌러 제자리 회전은 없다 |
| I4 | **걸음은 칸 단위로 끝까지 재생**하고 속도가 일정하다 | 한 칸 걷는 중에는 입력이 대기 | `createRepeat`, `STEP_MS` 간격으로 비슷하다 |
| I5 | **글자 찍기 속도를 설정**할 수 있다 (느림·보통·빠름) | 설정 메뉴 | `textSpeed`는 `normal`/`instant` 두 단계. `fast`가 없다 |
| I6 | **화면 전환 연출은 하나로 통일**한다 | 문·계단·전투 진입마다 같은 페이드 | `FADE_MS = 150`으로 통일되어 있다 |
| I7 | **자동 반복 입력.** 방향키를 누르고 있으면 계속 움직이고 떼면 멈춘다 | | 같다(`createRepeat`, 모달이 뜨면 모든 키를 뗌) |
| I8 | **터치 기기에는 가상 패드**를 둔다 | 해당 없음(원본은 물리 버튼) | 있다(`VirtualPad`, `pointer: coarse`) |

## 4. 안내와 학습 곡선 (B)

- 원본은 **긴 튜토리얼 대신 처음 장소를 조작 연습장으로** 만든다. 첫 방에서 걷고, 문을 지나고, 사람과 말하고, 사물을 조사하는 것을 자연스럽게 익힌다.
- 목표 안내는 "무엇을 해야 하는지"를 지도에서 읽게 하는 방향으로 짜였다. 이 프로젝트는 반대로 목표 띠를 화면에 두기로 결정했고(스펙 ①-b, `goal.ts`), 자유 탐색이 없다. 이 차이는 의도된 것이라 바꾸지 않는다.
- 이 프로젝트의 체험판 「사라진 물방울」(스펙 ③-d, 5분)이 이 역할이다.

## 5. 가져오지 않는 UI·UX

| 요소 | 이유 |
|---|---|
| 8px 글꼴과 4색 안에서 글자를 읽는 방식 | 본문 16px·고딕 규칙과 대비 검사(`contrast.test.ts`) 때문에 맞지 않는다 |
| 색만으로 상태를 구분하는 표시 | 이름표·아이콘을 함께 쓰는 규칙(렌즈 색 + 이름표)과 충돌한다 |
| 화면 전체 깜빡임, 빠른 점멸 연출 | 접근성 위험. `reducedMotion` 설정이 있고 점멸은 쓰지 않는다 |
| 물리 버튼 4개 기준의 조작 | 터치가 중심이다. 방향키는 터치 기기에서만 가상 패드로 보이고 지도 탭 이동이 주 수단이다 |
| 효과음·음악·그림·글꼴 | 참고 금지 규칙 |

## 6. 적용 후보

현재 코드와 비교해 **실제로 차이가 있는 것**만 골랐다.

| # | 후보 | 내용 | 규모 | 어디에 |
|---|---|---|---|---|
| U1 | 메뉴 커서 기억 | 모달·목록을 닫았다 다시 열 때 마지막 커서 위치를 복원한다. B로 한 장씩 벗겨지는 동작을 모든 모달에서 같게 맞춘다 | 작음 | `src/ui/modalStack.ts`, `ListWindow.tsx` |
| U2 | 글자 속도 3단계 | `textSpeed`에 `fast`를 더해 `normal`/`fast`/`instant`로 한다. 설정 메뉴(`MenuPanel`)에 항목이 하나 늘고 저장 형식(`Settings`)에 값이 하나 늘어난다 | 작음 | `state.ts`, `DialogueBox.tsx`, `MenuPanel.tsx`, `persist.ts`의 `validShape` |
| U3 | 선택지 커서·위치 규칙 점검 | `DialogueStep.choices`가 원본의 L4 규칙(대화 위 작은 창, 커서 표시, 키보드로도 고르기)을 따르는지 코드와 스크린샷으로 확인하고 어긋나면 맞춘다 | 작음 | `DialogueStep.tsx`, `dialogue.css` |
| U4 | 짧게 눌러 제자리 회전 | 정지 상태에서 방향키를 짧게 누르면 몸만 돌고, 오래 누르면 걷는다. 대화 상대를 향해 서기가 쉬워진다. **터치에서는 오조작이 늘 수 있어** 가상 패드에서는 쓰지 않는다 | 중간 | `src/field/repeat.ts`, `FieldScreen.tsx`. 입력 지연이 생기므로 시험 필요 |
| U5 | 팔레트 제한을 그림 기준으로 | 한 그림이 쓰는 색 수와 한 팔레트 안의 명암 단계를 `STYLE.md` 필수 항목으로 둔다(예: 같은 색상 계열 4단계 이내). 이미 "16색 이내"가 있어 규칙을 한 단계 더 구체화하는 것이다 | 작음 | `.claude/skills/nos-art/SKILL.md`, `src/art/validate.ts` |
| U6 | 저장 요약(이어하기 카드) | 장 제목, 저장 시각을 보인다 | — | 스펙 ④-a 3.4절에 이미 포함 |
| U7 | 메뉴 항목 설명 줄 | 목록·메뉴에서 항목을 고르면(포커스) 아래에 그 항목의 설명 한 줄을 틀 없이 보인다. 열기 전에 의미를 알게 한다. 에뮬레이터 캡처로 확인(A) | 작음 | `src/ui/ListWindow.tsx`, 하단 탭 시트 |
| U8 | 설정을 2열(라벨 \| 값) 화면으로 | `MenuPanel`의 설정(소리·글자 속도·글자 크기)을 라벨과 값 두 열로 정리하고 맨 아래에 「끝」을 둔다. 캡처로 확인(A) | 작음 | `src/mechanics/reflection/MenuPanel.tsx` |

**우선순위:** U1·U2·U3·U7·U8은 서로 독립이고 규모가 작아 하나의 작은 스펙("④-b 대화·메뉴 UX 다듬기")으로 묶을 수 있다. U4는 입력 체계를 건드려 별도로 시험해야 하고, U5는 아트 디렉션 하네스 수정이라 다른 작업과 섞지 않는다.

## 7. 다음에 확인할 것

- 에뮬레이터 화면 캡처로 L2·L4·L5의 실제 수치(상자 높이, 선택지 창 위치, 커서 모양)를 확인한다. **캡처 이미지는 저장소에 넣지 않는다.**
- U4(제자리 회전)는 프로토타입으로 입력 지연 체감을 확인한 뒤 결정한다.
- 이 문서의 항목은 스펙이 아니라 입력 자료다. 구현은 `brainstorming → spec → plan` 절차를 따른다.

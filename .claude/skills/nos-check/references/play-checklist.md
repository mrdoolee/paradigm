# 플레이 점검표

`nos-play-reviewer`가 스크린샷(`test-results/screens/<project>-<장면>.png`, project = `desktop` 1280×800, `tablet` 1024×768 터치)과 끝까지 플레이 결과를 이 표로 판정한다. 근거는 설계 문서 2·5·6절.

## A. 화면이 밀리지 않는다 (가장 중요)
- [ ] 게임 화면이 정수 배율(보통 2배, 960×720)로 가운데 있고, 남는 곳은 테두리 색이다. 가로·세로 스크롤이 없다.
- [ ] 대화창이 뜬 장면과 안 뜬 장면을 나란히 보면 **세계(지도·대륙)의 위치·크기가 똑같다.** 다르면 수정 필요.
- [ ] 대화창은 늘 같은 자리·같은 크기(아래쪽). 글이 길면 창이 커지지 않고 ▼·쪽 번호로 넘긴다.
- [ ] 선택지 창은 대화창 위 오른쪽, 커서 ▶. 대화창을 가리지 않는다.
- [ ] 안내 띠는 퍼즐 중에만 위쪽 한 줄(왼쪽 할 일, 오른쪽 진행 점). 대화창과 동시에 보이면 수정 필요.
- [ ] 퍼즐 핵심(움직일 대륙, 붙을 자리)이 대화창에 가려지지 않는다(위쪽 약 2/3 안).
- [ ] `desktop`과 `tablet`이 같은 배치다(배율만 같거나 다름). 한쪽에서만 잘리거나 겹치면 수정 필요.

## B. 도트가 또렷하다
- [ ] 그림·글자가 번지지 않는다(계단이 또렷, 중간색 테두리 없음). 소수 배율로 늘어난 흔적이 있으면 수정 필요.
- [ ] 글자가 실제 화면에서 16px 이상으로 읽힌다(Galmuri 11px × 2배).
- [ ] 이모지가 없다.

## C. 길을 잃지 않는다
- [ ] 퍼즐 중 이번에 움직일 대륙이 밝은 테두리로 구별되고, 나머지는 흐리다. 붙을 자리가 보인다.
- [ ] 안내 띠 문장이 지금 할 일과 맞는다. 진행 점이 단계와 맞는다.
- [ ] 틀린 자리에 놓았을 때 "틀렸다" 표시가 없다(그 자리에 머물 뿐).
- [ ] 장면이 바뀔 때 무엇이 일어났는지 한 줄 대사나 연출로 알 수 있다.

## D. 매끄럽고 짧다
- [ ] 끝까지 플레이에서 막히는 곳(누를 게 없는 화면, 끝나지 않는 대화)이 없다.
- [ ] 원고 총량 검사 통과(대화 쪽 수 상한). 장면별 대화가 몰린 곳이 있으면 적는다.
- [ ] 장면 전환이 1초 안팎이다. 긴 연출이 반복되지 않는다.
- [ ] 학생이 타이핑하는 곳이 없다.

## E. 그림 일관성 (그림 단계 뒤)
- [ ] 대륙·배경·초상·창 테두리가 한 가지 시각 언어(픽셀 밀도, 외곽선, 빛, 채도, 팔레트)다. STYLE.md(`activities/<id>/art/STYLE.md`)와 맞는다. 하나만 튀면 수정 필요.
- [ ] 대륙 윤곽이 실제 지도와 알아볼 만큼 닮았다.
- [ ] 실존 인물 초상에는 "원작 아님", 가상 인물에는 "가상 인물" 표시가 있다.
- [ ] 상업 게임(포켓몬스터 등)의 그림·글꼴을 베낀 흔적이 없다. 의심되면 판정 보류하고 알린다.

## 보는 범위와 판정
- 받은 스크린샷은 **전부** 연다. 못 본 장이 있으면 `통과`를 쓰지 않는다.
- 판정: `통과` 또는 `수정 필요`. 수정 필요면 줄마다 `항목 — project-장면 — 무엇이 어떻게 — 의심 원인 파일`.
- 취향은 적지 않는다. 이 표에 근거가 있는 것만.
